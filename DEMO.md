# Two-minute submission demo

1. **Open Home.** Explain the goal: keep a traceable link from a spoken commitment to a reviewed decision and an execution task. Counts come from the workspace; the initial historical ledger is sample data.
2. **Open Meetings.** Choose Launch conflict, or dictate the sample using Wispr Flow into the focused transcript field. The browser microphone is a separate optional input.
3. **Process meeting.** Identify the displayed extraction mode. With no key, describe it as limited offline rules, not a model running offline.
4. **Review the change.** Compare the active November 15 commitment with the proposed November 22 date. Expand the original transcript or task source quotes.
5. **Resolve and edit.** Select Replace earlier decision. Edit a task owner or deadline. Type or dictate `Reject task 2`, then submit. Confirm the review changes.
6. **Commit review.** Approved tasks reach the board. Rejected tasks are excluded. Move a task with its status buttons or drag it to another column.
7. **Open Memory.** Show the explicit replacement link, meeting-origin groups, and audit record. Refresh and confirm the same browser retains the workspace.
8. **Export.** Download a digest or JSON snapshot. No Slack, Jira, or email message is sent automatically.

## Strong technical explanation

AI assists messy-text extraction. The application owns the rules for conflict detection, review, allowed task mutations, supersession, source links, and execution. The same rules run in the browser and hosted API, so core work does not depend on a successful model response.

## Honest boundaries

Do not describe the demo as a collaborative cloud database, full semantic decision graph, Wispr SDK integration, or general offline language model. Do not promise latency or judging scores. Explain the limited rules and demonstrate an unsupported command making no changes.
